‘Could Not Access the Database’ in Basic PAYE Tools

Seeing ‘could not access the database’ in Basic PAYE Tools — often with a payroll deadline bearing down — is alarming, but your records are almost always recoverable. Here’s exactly what the message means, how to fix it without losing a thing, and when it’s worth handing to us. Rated 4.9 on Google.

/01 — THE QUICK ANSWER

What the ‘could not access the database’ error means

If Basic PAYE Tools shows ‘could not access the database’, it means the small database file the program keeps on your own computer has become corrupted, locked or moved — so the software can no longer open your payroll records. The safe fix is to close the program, take a full copy of its data folder first, then let Basic PAYE Tools rebuild a fresh database and restore your most recent automatic backup.

The single most important thing is what not to do: do not reinstall or ‘repair’ the software before you have copied your data. Your employees, pay history and RTI submissions live in a hidden folder on the PC, not in the program itself, so a careless uninstall or clean-up can wipe the only copy you have.

If your Full Payment Submission is due today and you cannot afford to experiment, that is exactly the sort of job we handle. We can usually take a look the same day over a secure remote session — see emergency IT help if the clock is against you.

/02 — WHY IT HAPPENS

The common causes behind the error

Basic PAYE Tools stores everything in a single SQLite database file on your computer. When that file cannot be opened, you get the ‘could not access the database’ message. There are a handful of common reasons.

  • A corrupted database. The program was closed mid-write — a crash, a power cut or the PC being switched off while it was still saving — and the file is now damaged.
  • Antivirus or Controlled Folder Access. Some security software locks or quarantines the database file, so Windows reports ‘access denied’ even though the file is still there.
  • Cloud sync interference. If the data folder or its backups sit inside OneDrive, Dropbox or another synced folder, the sync client can lock the file mid-upload and corrupt it. A live database should never live in a synced folder.
  • A different Windows user. The data is saved per Windows login. If you are signed into a new or renamed profile — common after an update or on a new PC — the tools open empty or cannot find the file.
  • A failed update or move. An interrupted Basic PAYE Tools update, or files copied to a new machine incorrectly, can leave the database in a state it cannot read.

Knowing which of these applies matters, because the fix for a corrupt file is very different from the fix for a permissions or profile problem.

/03 — COPY YOUR DATA FIRST

Before you touch anything, take a copy

Before you change a single thing, make a copy of your payroll data. This is the step that turns a stressful morning into a non-event.

Your Basic PAYE Tools data lives in a hidden folder. To find it, open File Explorer, click in the address bar, type %appdata% and press Enter. Open the HMRC folder, then payetools-rti. Inside you will see the database file and a backups folder containing dated automatic backups.

Copy the entire payetools-rti folder to somewhere safe first — your Desktop, or better still a USB stick — so you always have an untouched original to fall back on. If anything goes wrong later, you can put this copy back and be no worse off.

This is also why reinstalling is the wrong first move. Reinstalling the program does not repair a corrupt database, and some ‘fix it’ guides online tell you to delete or clear the data folder — which permanently destroys your pay history. Copy first, always. If you would rather not poke around in hidden folders at all, our backup and recovery and data recovery teams do this every week.

/04 — THE SAFE FIX, STEP BY STEP

Rebuilding the database and restoring your backup

Once you have a copy of the folder, the recovery itself is straightforward. In short: close the program, rename the database file so Basic PAYE Tools builds a fresh one, then restore your latest backup from inside the tools.

  • Close Basic PAYE Tools completely so nothing is holding the file open.
  • In the payetools-rti folder, rename the database file (often shown as sqlite3) — for example add an ‘x’ to the end. Do not delete it; you may still need it.
  • Reopen Basic PAYE Tools. With no database to read, it builds a new, empty one. This can take several minutes — let it finish.
  • From the homepage, choose ‘Restore your data’ and point it at your most recent backup in the backups folder. Restoring can also take a few minutes.
  • Check your data is back — your employer details, employees and last submission — before you file anything new.

If the tools still will not open, or the newest backup is older than your last pay run, stop there rather than risk your records. That is the point to get a pair of expert hands on it — guessing at this stage is how payroll data gets lost for good.

/05 — SHARED & NETWORKED SETUPS

If you run on a network or shared PC

The fix above is for the standard single-PC install. If your Basic PAYE Tools was set up to be shared — several people using it, or the database held on a server or mapped network drive — there are extra things that can break it, and the safe steps are different.

On a networked install, ‘could not access the database’ often points to a dropped connection to the shared folder, a permissions change, or two people having it open at once. The database file can also be locked by whichever machine opened it last. Renaming files on a shared setup without understanding the layout is risky, because you can orphan everyone else’s access.

This is very similar territory to other multi-user accounting databases — see our guide on Sage 50 multi-user cannot connect, and on QuickBooks and Sage running slow. If your payroll or accounts software is shared across the office, it is usually quicker and far safer to let us map the setup and fix it properly. Many local firms already rely on us for their accountancy and payroll IT support.

// GOOD QUESTIONS

Frequently asked

What does ‘could not access the database’ actually mean?

It means Basic PAYE Tools cannot open the database file where it stores your payroll records — usually because the file is corrupted, locked by other software, or saved under a different Windows user. Your data is normally still there; the program just cannot read it. The fix is to recover or rebuild that file safely, not to reinstall.

Will I lose my employees and RTI submissions?

Usually not. Basic PAYE Tools keeps automatic backups in a ‘backups’ folder alongside the database, so even a badly corrupted file can normally be restored to your last save. The real risk is human error — deleting the data folder or reinstalling before taking a copy. Copy the whole folder first and you protect yourself completely.

Should I just reinstall Basic PAYE Tools?

Not as your first step. Your data lives in a hidden AppData folder, not in the program, so reinstalling does not repair a corrupt database — and some uninstall or ‘clean-up’ routes delete your pay history. Always take a copy of the payetools-rti folder before reinstalling anything. If you are unsure, let us check it first.

Where is my Basic PAYE Tools data stored?

On the PC, in a hidden folder. Open File Explorer, type %appdata% in the address bar and press Enter, then open HMRC and payetools-rti. Inside is the database file and a backups folder. HMRC does not keep a copy for you, so this folder is your only record — back it up after every pay run.

Can antivirus or OneDrive cause this?

Yes. Security software or Controlled Folder Access can lock or quarantine the database file, and if the folder sits inside OneDrive or another synced location the sync client can corrupt the file mid-upload. A live payroll database should never live in a synced folder — if yours does, see our OneDrive troubleshooting or ask us to move it somewhere safe.

My deadline is today — what should I do right now?

Stay calm and do not reinstall anything. Take a copy of the payetools-rti folder, then try the rebuild-and-restore steps above. If it will not clear quickly, call us for emergency help — we can usually join you remotely the same day. HMRC can also advise on a late Full Payment Submission if one is genuinely needed.

Can you just fix this for me?

Yes — this is a common job for us. With your permission we connect to your PC over a secure remote session, copy your data safely, rebuild or restore the database, and confirm your records are back before you file. It is usually sorted the same day, and it is covered by our no-fix-no-fee promise. Call 01202 775566 to get started.

Do you support HMRC software even though it is free?

We support the Windows PC and the data around it — getting Basic PAYE Tools open, recovering the database and keeping backups safe. We are Windows and Android specialists. We do not give payroll or tax advice and cannot change your figures or submissions; for that you will deal with your accountant or HMRC. We just make sure the software works.
